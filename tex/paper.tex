\begin{abstract}
Models increasingly check what other models write. We measure one shipped arrangement against
ground truth no model supplies: an auditor from a different vendor reads the work, and deterministic
checks verify what code can verify. On general-purpose code with hidden tests, at least one of eight
independent readings flagged 30.0\% [20.0, 40.7] of defective programs that pass their visible
tests, and 16.0\% [10.1, 22.3] of correct ones, with diminishing returns and no plateau. That rate
belongs to a configuration, not to the auditor: the auditor route (model and sampling together),
one rulebook sentence and the counting rule each move it, and on a post hoc rating most missed programs fail where the specification's prose does not entail the value the hidden suite expects. Three preregistered studies then examine
scientific code, reported results and data. Checks that every reported number traces to its source
flagged every inconsistency and no fabrication written consistently into log, results and report;
the model auditor flagged nearly all such fabrications, twice on a wrong calculation
(on post hoc inspection). On data, a
documentation-derived validator and the model flagged overlapping but different faults, so together
they covered more than either. On scientific code with no tests shown, reframing the task around one
step sharply reduced flags on correct programs. Where both tiers ran, every flag on a clean item and
every wrong finding came from the model, partly by construction of the clean items. Studies making model calls were preregistered, the two
unregistered analyses are named, and every quoted report passed independent cross-vendor review.
\end{abstract}

\section*{Impact Statement}
This paper measures how well automated auditors of model-written code, results and data work, so its
main consequence is for how much such auditors should be trusted. The measurements argue against two
kinds of over-trust: a recall figure quoted without its false-positive rate and task framing, and a
deterministic provenance check read as a guarantee that a result is right, when it verifies only that
artefacts agree with each other. If adopted, the practices we argue for (reading every flag on items
built as clean, reporting operating points, pairing a model reader with executed checks) raise the
cost of audits but reduce false assurance in scientific and engineering work. A risk is that
published limits are used to game an auditor, for example by fabricating results consistently; we
report that weakness because a user of such systems needs to know it. All data are public benchmarks
and datasets under permissive licences, and no human subjects were involved.
