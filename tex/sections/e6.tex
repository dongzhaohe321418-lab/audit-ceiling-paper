\section{A randomised-contract audit experiment}
\label{sec:e6}

Section~\ref{sec:framework} states that computation cannot repair a miss on an indistinguishable case.
In a natural benchmark, we never observe the counterfactual contract. We construct it for each experimental unit:
a real benchmark task that leaves one behaviour open. We write two programs that differ only in that behaviour
and draw the contract used to grade the auditor independently of what it sees. We then either reveal or withhold the contract.

\subsection{Construction}
\label{sec:e6-construction}
\input{fig_design}

\paragraph{Contracts first.} For each of the 542 HumanEval+ and MBPP+ problems \citep{liu2023evalplus}, a proposer
model identifies one kind of valid input for which the task text and visible tests leave the behaviour open.
It states two rules as requirements a task author could add: \emph{B}, the benchmark reference's behaviour,
and \emph{A}, an equally specific alternative (for example, ``if several sublists are equally short, return the
first'' versus ``\dots the last''). Appendix~\ref{app:e6} groups the registered units by the kind of
behaviour left open (ties, readings of a phrase, Unicode conventions, repeated items, numeric types, degenerate
inputs). Two vendors then implement each rule from the task and the rule alone,
using the same prompt; no implementation sees the reference. Auditors read one vendor's A and B implementations,
which therefore share provenance and style. The vendor alternates across units.

\paragraph{Admission by execution.} An independent model writes a domain predicate \texttt{valid} and 16--24 probe
inputs; the proposer writes a class predicate \texttt{in\_class}. The checks cover the hidden suite, the proposer's
inputs, the probes, up to 300 seeded stress mutations (unusual whitespace, combining marks and other Unicode,
complex values equal to integers, negative indices, extreme and cancelling floating-point values, empty and
duplicated collections) and up to 40 inputs from a red-team model. That model sees all implementations and both
predicates and tries to break the admission conditions. Admission requires both B implementations to agree with
the reference on every valid input in these sets. Among these valid inputs, all four implementations must agree
with the reference outside the class; inside it, the two A implementations must agree. A and B must differ on at
least two valid class inputs, and every implementation must pass the visible tests. Each stage is attempted once
per problem; problems without a first-attempt primary unit received one second, independent attempt, fixed before
any held-out audit. These checks reject, for example, a ``correct'' B program whose integer summation silently
became floating point.

\paragraph{Judging without human raters.} Two models that neither proposed the rules nor serve as auditors (Claude Opus,
GPT-6.1-sol) judge whether the inputs are valid and each rule is compatible with the task's words and visible tests.
They are blind to which rule is the benchmark's and are instructed that a missing example is not permission.
The primary population comprises admitted units for which both judges accept the domain and both rules. We call these
\emph{execution-validated, two-model-compatible contract pairs}. They are not human-validated ambiguities, and we make
no claim about how common such ambiguity is.

\paragraph{Positive controls.} The same pipeline yields units whose evidence distinguishes the programs by asking
the proposer for a plausible \emph{misreading} that passes the visible tests but that the task's words rule out.
Both judges must call the misreading incompatible and the required rule compatible.

\subsection{Arms, auditors and scoring}
\label{sec:e6-arms}

Each open unit is audited under six arms, defined by the text appended to the task: nothing (\textsc{none}); both
rules as a numbered menu stating that the task does not say which applies (\textsc{menu}); the same menu plus ``the
function must follow rule ($k$)'', once for each rule (\textsc{resolve-a}, \textsc{resolve-b}); and one rule stated as
an ordinary requirement with no menu, once for each rule (\textsc{sentence-a}, \textsc{sentence-b}). A
\emph{reading} is one audit call; a \emph{cell} is a unit, program, arm and auditor configuration, read twice; a
\emph{configuration} is one auditor at one reasoning budget. Menu order is fixed per unit and independent of the contract. GPT-5.6-terra and
Claude Sonnet 5.5 each audit at a low and a high reasoning budget (\textsc{sentence} arms: low only), using the shipped rulebook and two readings per cell
(\NSixReadings{} readings in all, including the positive controls).

Under contract $X$, program $X$ is correct and the other is defective. In \textsc{none} and \textsc{menu}, the evidence
does not depend on the contract, so we score the same readings under both contracts. Lemma~\ref{lem:symmetric}
then forces flag recall to equal the false-flag rate; we report this equality as a check. A cell flags if either
reading reports a blocking finding. A diagnosis is \emph{verified} only if a flagging reading supplies a witness call
whose arguments have the benchmark's own types, that satisfies \texttt{valid} and lies in the class. On that call
the two contract oracles must differ, the program must disagree with the contract's oracle (the reference for B, the
other vendor's implementation for A) under the benchmark's own comparator, and the value the auditor says the call
should return must equal the oracle's. All of this is checked by execution. A unit's value is the mean over
configurations; intervals are problem-level bootstraps. We test the false-flag budget after resolution (10\%)
separately with a betting confidence bound \citep{waudbysmith2024betting}, which does not gate the other claims.

\subsection{Results}
\label{sec:e6-results}

The held-out population contains 41 units from 41 problems (34 from the first construction attempt and 7 from the
second) and 3{,}280 readings; the positive-control population contains 78 units. All hypotheses, intervals and the
order in which claims are tested were registered before the first held-out call.

\paragraph{Adding the requirement turns agreement into diagnosis.} One ordinary sentence stating the contract, with
no menu, raises verified diagnosis by \NSixFive{} points [\NSixFiveLo, \NSixFiveHi] over the task alone (E6-5); a menu
of both rules followed by a choice does as well (\NSixResolveCov\% against \NSixMenuCov\% with the undecided menu;
E6-1: +\NSixOne{} [\NSixOneLo, \NSixOneHi]). The undecided menu itself suppresses flagging, so E6-5 is the contrast
that answers what a stated requirement adds to the plain task. After the contract is stated, the flag rate on correct
programs is \NSixResolveFpr\%; its betting upper bound is \NSixResolveFprUp\% against the registered 10\% budget
(E6-1b, \NSixOneBVerdict).

\paragraph{Without the contract, auditors side with the benchmark.} In the \textsc{none} arm, recall equals the
false-flag rate by construction (\NSixNoneFlag\%), because the same readings are scored under both contracts. The
informative quantity is which program is flagged: the one that departs from the benchmark's behaviour is flagged
\NSixFlagPref{} points [\NSixFlagPrefLo, \NSixFlagPrefHi] more often than the one that follows it (an analysis the frozen
code computes but the registration does not list as a hypothesis), and verified diagnoses are \NSixTwo{} points
[\NSixTwoLo, \NSixTwoHi] more likely when the contract is the benchmark's rule (E6-2). We cannot say whether this
reflects memory of the benchmark or the most natural reading of the task, and the distinction does not matter for an
evaluation: independent solutions written from the task alone follow the benchmark's rule on these units almost
always (Appendix~\ref{app:e6}), so a hidden-test ``detection'' here credits agreement with the default reading,
which would be a false accusation had the task's author intended the other rule.

\paragraph{Reasoning budget.} After the contract is stated, the high budget changes verified diagnosis by
\NSixThree{} points (bootstrap [\NSixThreeLo, \NSixThreeHi]; betting [\NSixThreeBetLo, \NSixThreeBetHi]). The registered
equivalence claim (margin 10) is \NSixThreeVerdict: near the ceiling and at this sample size the data cannot
distinguish no effect from a moderate one, and we make no claim either way.

\paragraph{The vendors respond differently to an open question.} When told that the task leaves the choice open,
GPT passes \NSixGptPass\% of readings and Claude asks for clarification in \NSixClaudeAsk\% (Figure~\ref{fig:e6}c).
Neither flags. Both behaviours are defensible, but only one is visible to a benchmark that scores flag or pass.

\paragraph{Positive controls.} Where the task's words rule out one program, the same auditors separate the two
programs without any added text: flag recall minus false-flag rate is \NSixFourJ{} points [\NSixFourJLo, \NSixFourJHi]
(E6-4). The flat \textsc{none} arm of the open units therefore reflects evidence that does not decide, rather than an
auditor that cannot read.
